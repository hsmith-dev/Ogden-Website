What's inside

A working team, not a chat window.

All of it is in one codebase that you own and can read, change, and run wherever you like.

01

An autonomous backlog

Each project gets a real Kanban board. Assign a task to a persona and switch the project to autonomous so the crew works it on its own, or click Run now and drive each step yourself.

02

A crew you configure

Set each persona's name, prompt, model, temperature, and tool access. Talk to the whole team, or pull one aside.

03

Human-in-the-loop

With approval gates on, every run lands on its own branch. Read the real diff, then merge it or send it back with feedback.

04

Use any model you like

Bring your own keys. Different personas in the same project can use different providers, or you can keep everything on local models.

OpenAIAnthropicGemini OllamaOpenAI-compatibleMCP servers
05

A full audit trail

Token usage for every call, spend caps that stop runaway runs, run history, and a live activity log for each task.

06

Sandboxed and governed

Each project gets its own isolated git workspace. Role-based access, org-level isolation, and non-root containers are on by default.

Deployment

One codebase, two ways to run it.

Solo and Business are the same code and the same image. A single setting switches between them, and moving from one to the other needs no rewrite and no data migration tool.

Full setup guide →

Solo

SQLite · 1 user

One person on one machine. Docker Compose is all you need, and you're running in minutes.

$ cp .env.example .env
$ docker compose up --build

Business

Postgres · multi-user

Multi-user accounts with Viewer, Member, Admin, and Owner roles, and Postgres for concurrent writes. It still runs entirely on infrastructure you control.

$ docker compose -f docker-compose.yml \
    -f docker-compose.business.yml up --build
